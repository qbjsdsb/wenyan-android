# 自动巡检报告索引

> **AI 接手必读**：本目录由每小时自动巡检任务生成，记录项目健康状态。
> 新会话请按以下步骤操作。

## 接手流程

1. **读本文件** — 了解巡检机制与报告格式
2. **读最新报告** — `docs/auto-check/` 下按文件名倒序，最新文件名格式 `YYYY-MM-DD-HH.md`（UTC 时间）
3. **看"问题清单"** — 按 P0/P1/P2 优先级修复
4. **修复后本地验证** — `assembleDebug` + `testDebugUnitTest` 必须全绿才能 push
5. **更新报告标记** — 在最新报告对应问题后追加 `**已修复 + commit `<hash>`**`
6. **保留历史报告** — 不要删除或修改历史报告内容，只更新最新一份

## 巡检内容

每小时执行（北京时间整点）：
- `git pull origin main` — 拉最新代码
- `assembleDebug` — 编译验证
- `testDebugUnitTest` — 测试验证
- 静态扫描 — TODO/FIXME、docs 一致性、SESSION_LOG 同步状态
- 生成报告 + commit + push

## 报告格式

每份报告包含：
- **时间戳** — YYYY-MM-DD HH:MM UTC
- **HEAD commit** — 巡检时的仓库 HEAD
- **编译结果** — SUCCESSFUL / FAILED
- **测试结果** — X tests, Y failures, Z errors
- **静态问题清单** — 按优先级排序
- **历史问题追踪** — 从上一份报告继承未解决问题 + 本次新增 - 本次已修复

## 优先级定义

| 级别 | 含义 | 处理时机 |
|------|------|----------|
| P0 | 编译失败 / 测试失败 / 数据丢失 | 立即修复 |
| P1 | 功能逻辑错误 / 契约不一致 | 下次会话修复 |
| P2 | 代码质量 / 文档同步 / TODO 清理 | 有空时处理 |

## 历史问题追踪机制

- **累积位置**：每份报告末尾的"历史问题追踪"节，**不**在 README 里集中维护
- **继承规则**：下次巡检读上一份报告的"历史问题追踪"，继承未解决问题
- **去重规则**：同一问题（按文件+行号+错误类型）只记一次，不重复累积
- **关闭规则**：问题在最新报告里被标 `已修复 + commit <hash>` 后，下次巡检自动从累积清单移除

## 报告文件命名

- 格式：`YYYY-MM-DD-HH.md`（UTC 时间，HH 为 00-23 两位数）
- 示例：`2026-07-23-14.md` 表示 UTC 14:00（北京时间 22:00）的巡检
- **冲突处理**：若同一小时执行两次（如手动触发 + 定时触发），第二次在文件名后追加 `-2`，如 `2026-07-23-14-2.md`

## 报告清理策略

- **保留**：最近 7 天的报告（约 168 份）
- **清理**：超过 7 天的报告由巡检任务自动删除（仅删除文件，不影响 git 历史）
- **例外**：包含未解决 P0 问题的报告不删除，直到 P0 关闭
- **历史问题不丢失**：清理旧报告时，先把其中的未解决问题合并到最新报告的"历史问题追踪"

## 注意事项

- **巡检任务不自动修复代码** — 只检查 + 报告，修复由人或 AI 在新会话完成
- **沙箱环境无 emulator** — 无法验证运行时行为（UI 交互 / FSRS 调度 / 卡片翻转），这些需真机验证
- **CI 账单问题未解决** — GitHub Actions 无法兜底，巡检报告是当前唯一的质量保障
- **docs 一致性检查的判定**：00-STATUS 中的 hash 不需要等于 HEAD（它只在重要节点手动更新）。只有当 hash 指向一个不存在的 commit（`git rev-parse` 失败）时才列为 P1 问题；hash 有效但落后于 HEAD 属于正常现象，仅作信息记录
- **失败容错**：
  - `git pull` 冲突 → 报告记录"pull 冲突"，停止后续步骤
  - 编译/测试失败 → 仍生成报告，记录失败原因
  - `git push` 失败 → `git pull --rebase origin main && git push origin main`，仍失败则在下次巡检重试
  - 沙箱环境损坏（如 SDK 丢失）→ 报告记录"环境异常"，跳过编译/测试步骤
